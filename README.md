# БОГЕМА CMS

Backend (FastAPI) для интернет-СМИ + публичная витрина «БОГЕМА» на vanilla
HTML/CSS/JS. Админка — серверная, на Jinja2-шаблонах (`/admin`).

## Запуск

```bash
docker compose up --build
```

После старта:

- Публичный сайт: http://localhost:8000/
- Страница статьи: http://localhost:8000/article.html?slug=<slug>
- Админка: http://localhost:8000/admin  (admin / admin123)
- Публичный API: http://localhost:8000/api/articles

PostgreSQL поднимается в отдельном контейнере (порт хоста `5433`).

## Архитектура

```
backend/   FastAPI: API, админка, раздача статики фронтенда
frontend/  Публичная витрина (чистые HTML/CSS/JS, без сборки)
           - index.html      лента материалов
           - article.html    страница статьи
           - assets/css/     дизайн-система (светло-розовая / тёмная тема)
           - assets/js/      api, feed, article, theme
```

### Раздача фронтенда

Фронтенд раздаётся самим FastAPI как статика из корня (`StaticFiles(..., html=True)`),
смонтированная **последней** — поэтому она не перехватывает `/api/*`, `/admin/*` и `/uploads`.
Путь настраивается переменной окружения `FRONTEND_DIR`
(в docker-compose — `/app/frontend`, биндится через volume `./frontend`).

Так как фронт и API на одном origin, CORS не нужен.

## Публичное API

| Метод | Путь                       | Описание                                                  |
|-------|----------------------------|-----------------------------------------------------------|
| GET   | `/api/articles`            | Список опубликованных (`?page=&per_page=&section=&tag=`)  |
| GET   | `/api/articles/{slug}`     | Одна статья (с автором, сносками, фото, тегами, лайками)  |
| GET   | `/api/articles/{slug}/related` | Свежие статьи для блока «Читайте по теме»             |
| POST  | `/api/articles/{slug}/like`| Поставить лайк (один на браузер, без аккаунтов)           |
| GET   | `/api/sections`            | Разделы с количеством опубликованных статей               |
| GET   | `/api/tags`                | Теги с количеством опубликованных статей                  |
| GET   | `/api/settings/track`      | «Трек дня» (url + embed_url)                              |
| PUT   | `/api/settings/track`      | Сохранить «Трек дня» (админ)                              |

## Разделы и теги

- **Раздел** (категория) — один на статью. Фиксированный список:
  Мода, Музыка, Город, Люди, Культура (`app/core/sections.py`).
  В админ-форме выбирается из списка; в шапке сайта — навигация по разделам.
- **Теги** — произвольные, много на статью (many-to-many). В админ-форме
  вводятся через запятую; автоматически создаются при первом использовании
  и привязываются по slug. На статье показываются кликабельными чипами,
  фильтрующими ленту (`/?tag=<slug>`).
- Фильтрация по разделу/тегу — серверная (`?section=` / `?tag=`).

## Дизайн

Витрина стилизована под редакционный лонгрид в духе журнала «ЧТИВО»:
hairline-разделители, капитель для метаданных, табличный формат дат,
serif-заголовки статей.

- **Шрифты** (Google Fonts, бесплатные, с кириллицей):
  - логотип «БОГЕМА» — **Oswald** (узкий массивный гротеск, upper-case);
  - заголовки статей и подзаголовки — **Playfair Display** (serif);
  - тело текста — системный sans-serif.
- **Светлая тема** — мягкая светло-розовая «бумага» (`#fbecf0`).
- **Тёмная тема** — графит с розовым подтоном (`#16121a`).
- Переключатель темы в шапке; выбор сохраняется в `localStorage` и уважает
  системную тему при первом визите.
- **Буквица** (drop cap): первая буква статьи — крупная serif-заглавная
  акцентного цвета, обтекаемая текстом (в духе редакционных лонгридов).

## Картинки в статьях

У статьи есть **обложка** (`cover_image_url`) и **изображения в теле**.

Изображения в тексте вставляются через маркеры прямо в Markdown-тексте статьи:

```
Первый абзац текста…

![1]

Второй абзац…

![2]
```

В админ-форме статьи есть блок «Изображения в тексте»: загрузка файла
(через существующий `/api/admin/images/upload`), подпись и порядковый
номер. Номер маркера `![n]` соответствует порядку изображений в списке.
На странице статьи маркеры заменяются на `<figure><img><figcaption>` по
порядку. Картинки, для которых в тексте нет маркера, показываются
галереей в конце статьи.

## Трек дня (Яндекс Музыка)

На главной странице выводится блок «Трек дня» со встроенным плеером
Яндекс Музыки (через публичный embed-iframe, **без API-ключей и бесплатно**).

В дашборде админки есть форма «Трек дня»: в Яндекс Музыке открываете трек →
«Поделиться» → «HTML код», копируете код вставки и вставляете его в форму.
Бэкенд извлекает из кода embed-URL и сохраняет. Трек появляется на главной.
Можно вставить и обычную ссылку на трек — она тоже распознаётся.

## Возможности витрины

- Лента материалов с hero-карточкой свежего материала и сеткой карточек.
- **Фильтр по автору** (в рамках загруженной ленты) и **сортировка** (новые/старые).
- **Пагинация** кнопкой «Загрузить ещё».
- Страница статьи: рендер Markdown (`marked.js` + `DOMPurify`, самохостинг без CDN),
  сноски (`*` в тексте), изображения в теле (`![n]`), галерея.
- **Лайки** статей без аккаунтов: один лайк на браузер (защита по куке `voter_id`).
- **Тёмная тема** с переключателем и сохранением выбора.

## Ограничения

- Фильтр по автору работает по данным загруженной ленты. Для фильтрации по всем
  авторам во всём архиве нужен публичный `GET /api/authors` и параметр `author_slug`
  в `GET /api/articles` — может быть добавлен отдельно.
- Текст статьи рендерится как Markdown. Символы `*` в теле интерпретируются как
  маркеры сносок (в порядке появления) и ссылаются на записи `article.footnotes`;
  маркеры `![n]` — как ссылки на `article.images` по `position`.
